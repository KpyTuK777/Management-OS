## Status


## Authority

This document is the canonical architecture definition of accessibility for the
entire M6 Presentation Architecture. It owns the Accessibility Contract,
accessibility-obligation taxonomy, deterministic preservation rules,
accessibility degradation and recovery, the Platform Accessibility Adapter
boundary, and accessibility conformance.

It consumes all approved M6.1–M6.10 architecture documents without modifying
their meaning, objects, ownership, lifecycle, authority, state, composition,
interaction, navigation, rendering, or adapter contracts.

Accessibility is a first-class architectural concern. It is not a platform
feature, optional enhancement, visual variant, or post-rendering repair.

---

# 1. Purpose

The Accessibility Model ensures that canonical professional meaning and action
remain available when presentation is perceived, understood, navigated, or
operated through materially different modalities.

Accessibility preserves the canonical presentation contract; it does not create
an alternative domain model or a reduced professional experience.

The model:

- defines what accessibility must preserve across the Presentation
  Architecture;
- makes accessibility obligations explicit before platform realization;
- separates canonical obligations from platform accessibility mechanisms;
- requires equivalent professional outcomes without requiring identical
  physical expression;
- makes loss, limitation, fallback, and recovery deterministic and reviewable;
- provides one accessibility conformance result for each realization.

It does not prescribe how a platform satisfies an obligation.

---

# 2. Accessibility Principles

1. **Meaning Before Modality.** Canonical meaning exists independently of the
   modality used to express it.
2. **Equivalent Professional Access.** Every supported modality preserves
   access to the professional facts, distinctions, relationships, states, and
   consequences required for the same task.
3. **No Privileged Presentation.** Spatial, visual, audible, textual, tactile,
   gestural, sequential, or other expression is not canonical merely because it
   is primary on a platform.
4. **Semantics Are Source-Owned.** Accessibility exposes upstream meaning and
   never invents or reinterprets it.
5. **Operation Is Intent-Based.** Equivalent operation preserves canonical
   intent, preconditions, authority, commitment, cancellation, and outcome,
   not an input gesture or control mechanic.
6. **Structure Survives Re-expression.** Grouping, containment, order,
   hierarchy, boundaries, references, and context remain discoverable when
   physical arrangement changes.
7. **Redundancy Without Contradiction.** Multiple expressions may reinforce a
   distinction but cannot conflict or create a new canonical dimension.
8. **Continuity Is Mandatory.** Context, presentation focus, navigation origin,
   return, interruption, suspension, progress, and recovery survive modality
   change.
9. **Explicit Degradation.** Loss or limitation is never silent, ambiguous, or
   reported as equivalent.
10. **Recoverability.** When full expression is temporarily unavailable, the
    affected meaning, operation, and route to restoration remain explicit.
11. **Deterministic Resolution.** The same canonical inputs, obligations, and
    capability declaration produce the same accessibility disposition.
12. **Fail Closed.** A realization that cannot preserve an essential obligation
    is inaccessible for that scope, not approximately conformant.
13. **Adapter Neutrality.** The canonical model favors no platform,
    accessibility API, assistive technology, sensory channel, or input method.
14. **Professional Intent Preserved.** Alternative expression retains the
    calm, serious, evidence-led, and non-manipulative intent of Management OS.

# 3. Accessibility Contract

## 3.1 Definition

An **Accessibility Contract** is a versioned, implementation-independent set of
obligations that states how canonical meaning, structure, state, navigation,
interaction, presentation intent, degradation, and recovery must remain
discoverable, perceivable, understandable, and operable across supported
modalities.

It is not a platform accessibility tree, annotation set, input mapping, content
alternative, implementation interface, compliance checklist, or promise of
identical sensory output.

## 3.2 Ownership

This model owns:

- the Accessibility Contract descriptor and lifecycle;
- AO-01–AO-08 and their distinct accessibility responsibilities;
- applicability and obligation-resolution rules;
- accessibility preservation, modality-transition, degradation, and recovery
  rules;
- the three-layer accessibility adapter boundary;
- accessibility conformance evidence and verdicts.

All upstream models retain their ownership. In particular:

| Concern | Canonical owner |
| --- | --- |
| Professional and domain truth | Canonical Management Model and its owning models |
| Design Objects and relationships | Canonical Design Object Model |
| Semantic Roles and semantic dimensions | Canonical Design Semantics |
| Rendering Nodes, Rendering Tree, identity, and projection | Canonical Rendering Model |
| Symbolic presentation meaning | Semantic Token Architecture |
| Presentation State | Presentation State Model |
| Component responsibility | Canonical Component Model |
| Composition, Structural Regions, and Layout Intent | Composition and Layout System |
| Professional interaction intent and pattern progression | Canonical Operational Interaction Language and Canonical Interaction Patterns |
| Navigation truth and navigation representation | Canonical Operational Navigation, Navigation Governance, and Navigation Representation Model |
| Aggregate platform handoff and qualification | Rendering Contracts and Platform Adapters |

The Platform Accessibility Adapter owns only the mapping of a valid
Accessibility Contract to declared platform capabilities. Platform
Accessibility APIs own only technical mechanisms.

## 3.3 Contract descriptor

Every Accessibility Contract contains:

| Field | Required meaning |
| --- | --- |
| **Contract ID** | Stable accessibility-contract identity. |
| **Revision** | Immutable contract revision. |
| **Canonical sources** | Exact upstream contracts and revisions. |
| **Scope** | Canonical occurrences, states, interactions, and navigation representations governed. |
| **Required modalities** | Abstract modalities in which obligations must be satisfiable; no platform mechanism is named. |
| **Applicable obligations** | Exact AO-01–AO-08 obligations for the scope. |
| **Semantic order** | Source-derived order that must survive non-spatial presentation. |
| **Interaction equivalence** | Intent, preconditions, authority, outcomes, and recovery that must be preserved. |
| **Presentation equivalence** | Professional distinctions and intent that must remain perceivable without physical sameness. |
| **Continuity obligations** | Identity, context, focus, progress, origin, return, interruption, and modality-transition continuity. |
| **Degradation policy** | Source-authorized fallback order and prohibited loss. |
| **Recovery policy** | Conditions and path for restoring complete access. |
| **Evidence obligations** | Proof required for a deterministic verdict. |
| **Known limitations** | Explicit boundaries that remain visible to review. |

An incomplete descriptor is not a valid Accessibility Contract.

## 3.4 Responsibilities

The Accessibility Contract must:

1. enumerate all applicable obligations before platform mapping;
2. trace every obligation to exact canonical sources;
3. preserve distinctions among meaning, presentation state, domain state,
   navigation state, and platform state;
4. define equivalence by observable professional access and consequence;
5. preserve source-owned order, relationships, identity, and authority;
6. state permitted degradation and recovery before capability matching;
7. expose conflicts or unsupported essential obligations;
8. produce evidence without prescribing implementation.

It must not:

- add descriptions, labels, summaries, order, priority, hierarchy, or behavior
  that contradict canonical sources;
- make one modality authoritative over another;
- reduce an operation to its platform input mechanic;
- infer professional state from platform accessibility state;
- permit a platform limitation to rewrite a canonical obligation;
- treat technical availability as accessibility conformance.

## 3.5 Contract lifecycle

Accessibility Contract definitions follow:

```text
Proposed → Registered → Active → Deprecated → Retired
```

- **Proposed** is reviewable but cannot qualify a realization.
- **Registered** has a stable ID, complete descriptor, and source traceability.
- **Active** is mandatory for new accessibility qualification.
- **Deprecated** remains interpretable only for a declared transition period.
- **Retired** is historical and cannot govern a current realization.

A contract revision is immutable. Any changed source, obligation,
applicability, fallback, or evidence requirement creates a new revision.

Each realized accessibility projection follows:

```text
Required
    ↓
Resolved
    ↓
Validated
    ↓
Current
    ↓ source or capability revision changes
Superseded

Resolution or validation failure
    ↓
Inaccessible — Never Current
```

Lifecycle movement creates no domain event, interaction consequence, navigation
transition, or canonical history.

# 4. Accessibility Taxonomy

## 4.1 Admission and exclusivity

An accessibility obligation category is canonical only when it owns a distinct
preservation responsibility, is observable across modalities, traces to an
upstream contract, and cannot be fully represented by another category.

Every obligation has one primary AO owner. References across categories do not
duplicate ownership.

## 4.2 AO-01 Semantic Discoverability

Ensures that canonical identity, role, purpose, state, qualification,
relationships, provenance, authority, consequence, and available action can be
found and understood independently of incidental presentation.

It requires:

- every meaningful occurrence to retain source identity and Semantic Role;
- independent semantic dimensions to remain independently discoverable;
- labels, descriptions, references, and qualifications to agree with canonical
  meaning;
- state and change to be distinguishable from static content;
- hidden, decorative, or incidental expression never to carry unique
  professional meaning;
- ambiguity to be exposed rather than resolved by platform inference.

AO-01 does not create semantic meaning or domain metadata.

## 4.3 AO-02 Operability

Ensures that every available canonical interaction can be initiated, progressed,
confirmed, cancelled, completed, retried, interrupted, or recovered through an
equivalent supported modality.

It preserves:

- professional intent and participant roles;
- preconditions, validation, authority, and freshness;
- distinction between inspection, selection, adoption, and commitment;
- reversible and irreversible boundaries;
- idempotency and one canonical consequence;
- feedback, progress, failure, cancellation, and recovery;
- operation without dependence on one physical gesture, timing assumption, or
  sensory channel.

AO-02 does not define input methods or controls.

## 4.4 AO-03 Perceivability

Ensures that required content, distinctions, state, feedback, warnings,
relationships, and changes can be perceived through every modality declared
for the applicable scope.

It requires:

- no essential meaning to depend on one sensory property;
- canonical distinctions to have non-conflicting equivalent expressions;
- current content and material change to remain distinguishable;
- provenance, uncertainty, authority, and consequence to remain perceivable;
- transient presentation not to make durable professional meaning
  unrecoverable;
- absence, unavailability, and indeterminacy to be expressed truthfully.

AO-03 does not define color, sound, contrast, typography, timing, animation, or
other physical values.

## 4.5 AO-04 Structural Navigation

Ensures that a person can orient within, traverse, inspect, skip, enter, leave,
and return through canonical presentation structure without relying on physical
placement.

It preserves:

- Rendering Tree parentage and semantic order;
- Component boundaries and responsibilities;
- Composition relationships, Structural Regions, and Layout Intent;
- current context, destination, origin, return, interruption, and suspension;
- presentation focus distinct from Current Focus and selection;
- stable identity across traversal and replacement;
- recovery when structure changes or becomes incomplete.

AO-04 does not own professional navigation or platform traversal mechanics.

## 4.6 AO-05 Interaction Equivalence

Ensures that alternative interaction modalities lead through equivalent
canonical decisions to equivalent professional outcomes.

Equivalence requires the same:

- intent and action eligibility;
- material information available before commitment;
- authority and validation requirements;
- commitment boundary and canonical consequence;
- cancellation, retry, interruption, correction, and recovery semantics;
- feedback sufficient to know whether an outcome occurred.

The number, sequence, or physical form of platform actions may differ only when
these obligations remain intact. Faster, shorter, or simplified interaction is
not equivalent if it removes a professional safeguard.

## 4.7 AO-06 Presentation Equivalence

Ensures that alternative expressions preserve the professional interpretation
and intent of the canonical presentation without requiring identical
appearance, geometry, density, sequence, duration, or sensory character.

It preserves:

- semantic hierarchy and relative professional emphasis;
- independent status, certainty, authority, attention, currentness, and
  lifecycle distinctions;
- evidentiary seriousness, calmness, restraint, and non-manipulative tone;
- grouping, boundaries, provenance, and relationship strength;
- difference between recommendation, fact, warning, history, and action;
- production and non-production distinctions.

Presentation equivalence cannot be claimed merely because the same words or
operations remain technically present.

## 4.8 AO-07 Degradation

Ensures that any accessibility limitation is explicit, scoped, attributable,
and reviewable.

Every degradation records:

- affected canonical occurrence and obligation;
- unavailable modality or capability;
- meaning, operation, structure, or continuity at risk;
- selected source-authorized fallback;
- preserved and unpreserved properties;
- user-relevant limitation and consequence;
- recovery condition and evidence;
- disposition: Equivalent, Explicitly Degraded, or Inaccessible.

Degradation never authorizes fabrication, silent omission, false completion,
hidden inoperability, or semantic approximation.

## 4.9 AO-08 Recovery

Ensures that accessible professional work can resume after interruption,
capability loss, stale projection, invalid structure, failed interaction, or
modality transition.

Recovery preserves:

- canonical object and occurrence identity;
- actor, authority, context, and source revisions;
- last valid presentation and interaction state;
- completed versus uncommitted consequences;
- navigation origin, return, suspended intent, and change since departure;
- explicit missing or stale information;
- deterministic restoration from current canonical sources.

Recovery does not replay a committed consequence, infer success, rewrite
history, adopt a context automatically, or create canonical truth.

# 5. Accessibility Preservation Rules

## 5.1 Semantic preservation

1. Every accessible occurrence traces to the same canonical source and revision
   as its presentation occurrence.
2. Semantic Role, identity, state, qualification, provenance, authority, and
   consequence remain distinguishable.
3. Independent dimensions cannot be collapsed into a single inaccessible
   signal or combined description.
4. Alternative expression may clarify source meaning but cannot add an
   unsupported conclusion.
5. Decorative or platform-generated content cannot become the sole carrier of
   professional meaning.
6. Summarization is admissible only when the complete canonical meaning remains
   reliably discoverable and the summary does not replace required detail.
7. Historical, current, proposed, recommended, unavailable, and indeterminate
   information remain distinct.

## 5.2 Interaction outcome preservation

1. Every available canonical interaction has an equivalent operable path.
2. Equivalent paths invoke the same Canonical Interaction Pattern and
   professional intent.
3. Preconditions, authority, validation, freshness, and concurrency remain
   identical in meaning.
4. Alternative operation cannot bypass review or confirmation obligations.
5. Commitment occurs once at the canonical commitment boundary.
6. Cancellation before commitment produces no canonical consequence.
7. Retry cannot duplicate a consequence.
8. Completion, failure, partial progress, and recovery are unambiguous.
9. A modality change during an interaction preserves valid progress or returns
   explicitly to the last recoverable state.

## 5.3 Navigation continuity preservation

1. Semantic traversal order derives from canonical structure, not physical
   coordinates or framework defaults.
2. Current professional context remains explicit throughout structural
   traversal.
3. Presentation focus, selection, Current Focus, and navigation adoption remain
   separate.
4. Origin, valid return, interruption, and suspended context survive modality
   change.
5. Replacement preserves stable occurrence identity and the nearest valid
   semantic continuation point.
6. Removed or invalid targets lead to an explicit qualified recovery target.
7. Structural navigation cannot create a professional navigation transition.
8. Context abandonment is never inferred from leaving a presentation region.

## 5.4 Professional-intent preservation

1. Alternative presentation preserves hierarchy without manufacturing urgency
   or flattening material distinctions.
2. Evidence, provenance, uncertainty, and authority remain available before
   consequential action.
3. Warning and interruption expression remains proportional to source-owned
   significance.
4. Repetition, sequencing, or modality cannot be used to manipulate attention
   beyond canonical priority.
5. Concision cannot remove professional safeguards or material context.
6. Production, learning, simulation, history, and recommendation remain
   unmistakably distinct.
7. Accessible expression remains suitable for serious, sustained professional
   reasoning.

## 5.5 Deterministic resolution

Accessibility resolution accepts:

- exact canonical presentation inputs and revisions;
- the active Accessibility Contract revision;
- applicable AO-01–AO-08 obligations;
- declared abstract modality and accessibility capabilities;
- current presentation, interaction, and navigation state;
- prior valid accessible projection where continuity applies;
- source-authorized fallback order.

```text
Validate Canonical Inputs
        ↓
Determine Applicable AO Obligations
        ↓
Resolve Direct Equivalent Expressions and Operations
        ↓
Resolve Structure, Order, and Continuity
        ↓
Evaluate Authorized Fallbacks
        ↓
Validate Degradation and Recovery
        ↓
Publish Complete Accessibility Disposition
```

Identical inputs produce equivalent obligation coverage, semantic order,
operation mapping, continuity result, fallback selection, degradation state,
and verdict. Platform preference and framework defaults cannot affect the
result.

# 6. Degradation and Recovery

## 6.1 Ordered degradation policy

When a direct accessible capability is unavailable, evaluate only:

1. an equivalent expression or operation in the current modality;
2. an equivalent expression or operation in another supported modality;
3. a serialized expression preserving identity, order, relationships, state,
   intent, and consequence;
4. a source-authorized summary or deferred operation that preserves reliable
   access to the complete source and next valid action;
5. an explicit degradation preserving every essential obligation and exposing
   the limitation;
6. Inaccessible.

The first conformant alternative is mandatory. Convenience, cost, or platform
preference cannot reorder fallback.

## 6.2 Dispositions

- **Equivalent** — every applicable obligation is fully preserved.
- **Explicitly Degraded** — a source-authorized fallback preserves all
  essential meaning and operation while a bounded limitation is exposed.
- **Inaccessible** — any essential meaning, distinction, structure, operation,
  continuity, consequence, or recovery obligation cannot be preserved.

Explicitly Degraded is never reported as Equivalent. Inaccessible scope cannot
be made current or offered as a complete professional path.

## 6.3 Recovery rules

Recovery:

1. validates current actor, authority, canonical revisions, and capabilities;
2. identifies the last valid accessible projection and uncommitted work;
3. reconciles all source and state changes;
4. recomputes AO applicability and fallback from current sources;
5. preserves completed canonical consequences without replay;
6. restores context, semantic continuation, origin, return, and suspended
   intent where still valid;
7. exposes stale, missing, changed, or inaccessible obligations;
8. validates the entire replacement projection;
9. replaces the degraded projection atomically.

Improved accessibility capability creates no domain event merely because a
better presentation becomes available.

# 7. Adapter Boundary

## 7.1 Boundary

```text
Canonical Accessibility Model
        ↓  Accessibility Contract
Platform Accessibility Adapter
        ↓  Meaning-preserving technical mapping
Platform Accessibility APIs
```

No lower layer may bypass the layer immediately above it or reinterpret an
upstream canonical source.

## 7.2 Canonical Accessibility Model

The canonical layer:

- owns AO-01–AO-08, applicability, preservation, fallback, recovery, and
  evidence obligations;
- binds obligations to exact M6 source contracts;
- defines equivalence and prohibited loss;
- remains independent of platform capability and implementation;
- produces a complete Accessibility Contract for adapter qualification.

It does not choose technical representations, platform objects, attributes,
events, input methods, services, or APIs.

## 7.3 Platform Accessibility Adapter

The adapter:

- consumes one valid current Accessibility Contract;
- declares supported abstract capabilities and limitations;
- maps each obligation to a direct capability or authorized fallback;
- preserves identity, semantics, order, structure, state, interaction outcome,
  navigation continuity, and professional intent;
- exposes degradation and recovery;
- keeps canonical, adapter, and platform state distinguishable;
- supplies reproducible conformance evidence;
- rejects obligations it cannot preserve.

The adapter may choose mechanisms but cannot choose different canonical
meaning, applicability, outcome, fallback order, or verdict criteria.

## 7.4 Platform Accessibility APIs

Platform Accessibility APIs:

- provide technical exposure, traversal, notification, input, state, and
  interoperability mechanisms;
- realize only adapter mappings;
- report technical capability and failure;
- may optimize mechanics without changing accessibility outcomes;
- establish no canonical semantics, authority, state, navigation, interaction,
  degradation, or conformance.

API availability is not evidence that an obligation is satisfied.

## 7.5 Boundary failures

The boundary fails if:

- platform metadata becomes a source of canonical meaning;
- an adapter infers semantics or order from framework defaults;
- platform focus becomes Current Focus or canonical selection;
- a technical action bypasses canonical interaction safeguards;
- platform traversal becomes professional navigation;
- a missing capability silently removes content or operation;
- an API-specific construct enters the canonical contract;
- an adapter reports accessibility without complete AO evidence.

# 9. Conformance Evidence and Verdict

## 9.1 Required evidence

An accessibility qualification package contains:

- exact Accessibility Contract, source revisions, and capability declaration;
- AO-01–AO-08 applicability and coverage matrix;
- traceability from every accessible occurrence to its canonical occurrence;
- semantic identity, distinction, state, and discoverability evidence;
- perceivability evidence across each declared modality;
- structural order, region, relationship, focus, and continuity evidence;
- interaction intent, authority, commitment, cancellation, retry, feedback,
  interruption, and recovery evidence;
- presentation-equivalence evidence for hierarchy and professional intent;
- modality-transition and atomic-replacement evidence;
- direct mappings, fallback selections, degradation disclosures, and recovery
  results;
- Equivalent, Explicitly Degraded, and Inaccessible scenarios;
- deterministic rerun evidence;
- prohibited-boundary-transformation audit and known limitations.

Evidence demonstrates observable architecture obligations. It cannot require or
privilege one implementation technique.

## 9.2 Deterministic verdict

```text
Conformant
```

requires complete AO coverage, an Equivalent or valid Explicitly Degraded
disposition for every applicable obligation, no inaccessible essential
obligation, no prohibited transformation, complete reproducible evidence, and
exclusive layer ownership.

Otherwise:

```text
Non-conformant
```

No partial, implied, platform-certified, or mechanism-based architecture
conformance verdict is permitted.
