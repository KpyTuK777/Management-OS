# M6.9 — Navigation Representation Model

## Status

```text
Approved for M6 dependency use
Milestone M6
```

## Authority

This document is the single source of truth for representing canonical
navigation inside M6 presentation architecture. It defines representation
identity, ownership, lifecycle, taxonomy, deterministic projection, exposure,
continuity, replacement, degradation, recovery, the Platform Navigation
Framework boundary, and conformance.

The Navigation Representation Model represents Operational Navigation and
Navigation Governance contracts. It never owns navigation, professional
attention, context adoption, Current Focus, interruption classification,
suspension, return validity, navigation transition authority, or navigation
history.

# 1. Purpose

Operational Navigation defines professional movement among valid contexts.
Navigation Governance defines the laws that govern attention, priority,
interruption, authority, explainability, and recovery. M6 must project those
contracts into Rendering Nodes, Components, Composition Plans, Semantic Tokens,
Presentation State, and Interaction Patterns without turning platform
navigation mechanics into professional truth.

```text
Operational Navigation state projection
        +
NT-01–NT-22 navigation transition graph
        +
NAV-01–NAV-33 governance
        +
Context Envelope, authority, and Memory references
        ↓
Navigation Representation Resolution
        ↓
Validated Navigation Representation Set
        ↓
Platform Navigation Framework
```

The model answers:

> Which navigation meaning must be represented now, and what continuity must be
> preserved?

It does not decide which professional context becomes active.

# 2. Representation Principles

1. **Projection, Never Ownership.** Representation consumes navigation truth and
   cannot author it.
2. **Context, Not Location Mechanic.** Current representation identifies adopted
   professional context, not a platform location.
3. **Transition Evidence Required.** Origin, destination, interruption, and
   return derive from valid navigation transition contracts.
4. **One Active Context.** Representation cannot imply several simultaneously
   adopted professional contexts.
5. **Focus Preserved, Not Created.** Current Focus is referenced exactly as
   Navigation owns it.
6. **Destination Is Not Adoption.** Availability never means selected, active,
   authorized for all acts, or entered.
7. **Origin Is Meaningful Context.** Origin preserves intent and continuity, not
   a previous platform location.
8. **Return Is Qualified.** Return representation includes freshness, authority,
   change-since-departure, and validity conditions.
9. **Interruption Is Exclusive.** One concern has one Navigation Governance
   interruption class; representation cannot aggregate escalation.
10. **Suspension Is Not Resolution.** Suspended navigation preserves unfinished
    intent without implying completion or abandonment.
11. **History Is Read-Only Projection.** Navigation history representation reads
    source-owned consequential history and creates no parallel timeline.
12. **Deterministic Projection.** Equivalent canonical navigation input produces
    an equivalent representation set.
13. **Explicit Degradation.** Missing, stale, inaccessible, or indeterminate
    navigation meaning is stated rather than fabricated.
14. **Atomic Replacement.** A complete valid representation set replaces an
    obsolete set as one projection.
15. **Adapter Neutral.** Meaning survives materially different platform
    navigation mechanics.
16. **Accessible Equivalence.** Current context, destinations, origin, return,
    interruption, suspension, and recovery remain recoverable.
17. **No Implicit Authority.** Exposure, ordering, emphasis, proximity, or
    persistence grants no authority.
18. **No Domain Consequence.** Representation creates no canonical event,
    lifecycle change, interaction commitment, or Current Situation.

# 3. Navigation Representation Contract

## 3.1 Representation set

A Navigation Representation Set is an immutable, generation-scoped projection
for one actor and one current navigation-state revision:

```text
Navigation Representation Set
  ├─ one active-context representation
  ├─ zero or more available-destination representations
  ├─ zero or one direct-origin representation
  ├─ zero or one qualified-return representation
  ├─ zero or one active-interruption representation
  ├─ zero or more suspended-context representations
  ├─ zero or more contextual-navigation representations
  ├─ zero or one history-inspection representation
  └─ completeness, degradation, and recovery result
```

The set is not canonical Navigation State, Context Envelope, professional
history, information architecture, or platform navigation state.

## 3.2 Ownership

Navigation Representation Model owns only:

- NR-01–NR-08 representation categories and descriptors;
- deterministic mapping from canonical navigation projection to M6 contracts;
- representation exposure and continuity rules;
- representation-set replacement, degradation, and recovery;
- the Platform Navigation Framework boundary;
- representation conformance.

Ownership remains outside this model for:

| Concern | Owner |
|---|---|
| Navigation layers, contexts, state projection, Current Focus, NT graph, and movement validity | Canonical Operational Navigation |
| Attention, priority, interruption class, aggregation prohibition, authority, explainability, and recovery laws | Operational Navigation Governance |
| Context Envelope | Workbench Canonical Domain Model |
| Consequential history and reconstruction | Operational Memory |
| Professional interaction intent | Canonical Operational Interaction Language |
| CIP-09–CIP-11 orchestration | Canonical Interaction Patterns |
| Navigation Rendering Node and Semantic Role | Canonical Rendering Model and Canonical Design Semantics |
| Navigation Component responsibility | Canonical Component Model |
| Navigation Structural Region and Layout Intent | Composition and Layout System |
| Platform navigation mechanics | Platform Navigation Framework |

## 3.3 Representation descriptor

Every representation occurrence declares:

| Field | Requirement |
|---|---|
| **Representation ID** | Generation-scoped projection identity. |
| **Category** | Exactly one NR-01–NR-08 category. |
| **Navigation-state revision** | Exact source projection revision. |
| **Actor and authority scope** | Current actor plus attributable authority source and limits. |
| **Context identity** | Matter/non-production boundary, layer, dominant object, and intent. |
| **Focus reference** | Active, suspended, displaced, or absent Focus as Navigation owns it. |
| **Navigation transition reference** | Applicable NT ID, source, destination, preconditions, authority, and continuity. |
| **Context Envelope reference** | Single canonical continuity contract and relevant validity. |
| **Origin and return** | Exact preserved identities, conditions, and change-since obligations. |
| **Interruption data** | Exclusive class, basis, disposition, displaced context, and return where applicable. |
| **History source** | Operational Memory/source references where applicable. |
| **M6 bindings** | RN, DSR, STC, PSD, CCT, SR, and CIP references. |
| **Exposure obligation** | Required, conditional, or prohibited representation. |
| **Degradation and recovery** | Missing/stale source, approved fallback, and next valid path. |
| **Prohibited implications** | Meaning representation and framework mechanics cannot add. |

# 4. Representation Lifecycle

Navigation Representation definition lifecycle is governed through Architecture
Review. Each representation-set instance follows a disposable projection
lifecycle:

```text
Required
    ↓
Derived
    ↓
Validated
    ↓
Current
    ↓ source navigation revision changes
Obsolete

Derivation or validation failure
    ↓
Invalid — Never Current
```

| Condition | Meaning | Permitted consequence |
|---|---|---|
| **Required** | A current canonical navigation revision needs representation. | Begin derivation from exact sources. |
| **Derived** | Candidate NR occurrences and bindings are known. | Validate completeness, authority, continuity, and degradation. |
| **Validated** | The full set conforms to all contracts. | Atomically become current. |
| **Current** | The set represents the exact active navigation revision. | Be consumed by a Platform Navigation Framework. |
| **Obsolete** | Source navigation or M6 projection revision changed. | No longer represent current navigation. |
| **Invalid** | Required meaning, source, authority, continuity, or mapping failed. | Never replace the prior valid set. |

Representation lifecycle creates no navigation transition, Memory Event, or
domain lifecycle condition.

# 5. Navigation Representation Taxonomy

## 5.1 Admission rule

A representation category exists only when it:

- corresponds to a distinct field or governed condition in canonical
  Navigation;
- has one stable representation responsibility;
- cannot merge with another category without losing continuity or authority;
- remains meaningful across materially different platform frameworks;
- owns no navigation meaning.

## 5.2 NR-01 Current Context Representation

Represents the one professional context currently adopted for the actor.

Required source:

- active layer L1–L8;
- Matter or governed non-Matter identity;
- dominant object and professional intent;
- Current Focus reference where applicable;
- authority orientation;
- Context Envelope validity;
- current Navigation State revision.

It must not imply that a platform location, selected item, or visible component
alone constitutes professional context adoption.

## 5.3 NR-02 Available Destination Representation

Represents one destination currently available for deliberate adoption or
qualified inspection.

Required source:

- exact destination context and layer;
- applicable NT contract;
- entry preconditions and current eligibility;
- actor authority and access;
- expected continuity, consequence, origin, and return;
- unavailable or indeterminate reason where professionally necessary.

Availability is not adoption, authority for destination actions, lifecycle
progression, or promise of successful entry.

## 5.4 NR-03 Origin Representation

Represents the professional context directly displaced by deliberate navigation
or governed interruption.

Required source:

- origin context and source revision;
- attributable navigation transition;
- prior intent, dominant object, and Focus reference;
- unfinished work and last meaningful act;
- relationship to current context;
- validity and retention boundary.

Origin is not an unqualified previous location or historical truth.

## 5.5 NR-04 Return Representation

Represents the best currently valid deliberate return to a preserved origin or
recovery target.

Required source:

- target context and originating navigation transition;
- intended return condition;
- current authority and source availability;
- freshness and change-since-departure;
- affected assumptions and required revalidation;
- fallback when the original target is invalid.

Return represents restored meaning, not restoration of platform position.

## 5.6 NR-05 Interruption Representation

Represents one governed interruption and its effect on displaced professional
attention.

Required source:

- exactly one interruption class;
- attributable material basis and provenance;
- affected active context and displaced Focus;
- priority distinction without hidden score;
- current disposition and authority;
- suspended context and reliable return;
- explicit reclassification basis where applicable.

Representation cannot escalate through repeated weak signals, merge classes,
hide Watson recommendation, or treat delivery mechanics as governance.

## 5.7 NR-06 Suspended Context Representation

Represents a valid professional context preserved while not currently active.

Required source:

- suspended context identity and Context Envelope;
- unfinished intent, Focus state, and last meaningful act;
- suspension reason and authority;
- source revisions and freshness;
- next justified return condition;
- replacement, supersession, completion, or abandonment status.

Suspended does not mean resolved, closed, inactive domain state, or safe to
discard.

## 5.8 NR-07 Contextual Navigation Representation

Represents navigation choices and orientation that are meaningful only inside
the active context.

Required source:

- active context, layer, and dominant object;
- exact local destination or inspection context;
- applicable NT or OI contract;
- relationship to current professional intent;
- origin and return;
- authority, availability, and degradation.

Contextual navigation cannot create a new navigation layer, hidden context,
local Context Envelope, or domain hierarchy.

## 5.9 NR-08 Navigation History Representation

Represents an authorized read-only inspection of consequential context changes.

Required source:

- Operational Memory and owning source history references;
- attributable actor, navigation transition, context, time, and basis;
- interruption, suspension, return, recovery, or correction evidence;
- historical/current distinction;
- query scope, source availability, and retention limits;
- current-context return target.

This category creates no navigation log, parallel timeline, canonical history,
or authority. Presentation-local movement is excluded unless an owning source
made it consequential.

# 6. M6 Representation Mapping

## 6.1 Required bindings

| Navigation category | Primary M6 binding | Supporting bindings |
|---|---|---|
| **NR-01 Current Context** | RN-07 / DSR-10 / CCT-06 in SR-02 | STC-01, STC-05; PSD-01/02/08; context-bearing CCT-01/CCT-02 |
| **NR-02 Available Destination** | RN-07 / DSR-10 / CCT-06 | RN-08 + CIP-09 where adoption is offered; RN-09/RN-10 for qualification |
| **NR-03 Origin** | RN-07 / DSR-10 / CCT-06 | STC-05; typed reference to prior context; LI-05/LI-08 |
| **NR-04 Return** | RN-07 / DSR-10 / CCT-06 | RN-08 + OI-52/CIP-09; RN-09/RN-10 for validity and feedback |
| **NR-05 Interruption** | RN-07 / DSR-10 / CCT-06 | CIP-10; RN-09 for class; RN-10/CCT-08 for disposition and recovery |
| **NR-06 Suspended Context** | RN-07 / DSR-10 / CCT-06 | STC-05; PSD qualification; typed origin/return reference |
| **NR-07 Contextual Navigation** | RN-07 / DSR-10 / CCT-06 | CCT-04/CCT-05 references; RN-08; CIP-09 |
| **NR-08 Navigation History** | RN-05/RN-06 inspection projection with DSR-08/DSR-09 | CCT-04/CCT-05; CIP-12/OI-57; CCT-06 return representation |

NR-08 uses history-inspection representation rather than making history itself a
Navigation Node.

## 6.2 Token and Presentation State rules

1. Every category resolves STC-01 for its DSR role.
2. STC-05 carries origin, return, suspension, interruption, continuity, and
   recovery obligations.
3. STC-02 dimensions remain independent; interruption class, authority,
   attention, currentness, and availability cannot collapse.
4. PSD-01 governs current exposure only after the representation obligation is
   resolved.
5. PSD-02 describes presentation capability, not destination eligibility or
   navigation authority.
6. PSD-03 may express source-owned emphasis but creates no priority.
7. PSD-05 Selection and PSD-06 Presentation Focus never adopt a professional
   context or Current Focus.
8. PSD-08 degradation must match the representation-set degradation contract.

# 7. Deterministic Projection Rules

## 7.1 Input contract

Projection accepts:

- one current Operational Navigation State revision;
- L1–L8 layer contracts and NT-01–NT-22 graph revision;
- NAV-01–NAV-33 governance revision;
- actor identity, authority, and access;
- active and suspended Context Envelope references;
- Focus, dominant object, origin, return, interruption, and recovery fields;
- Operational Memory/source history availability;
- current RN, STC, PSD, Component, Composition Plan, and CIP revisions;
- Platform Navigation Framework capability declaration;
- prior valid representation set where replacement applies.

## 7.2 Resolution pipeline

```text
Validate Navigation State and Governance Revisions
        ↓
Resolve NR-01 Current Context
        ↓
Resolve Valid NR-02 Destinations
        ↓
Resolve NR-03 Origin and NR-04 Return
        ↓
Resolve NR-05 Interruption and NR-06 Suspensions
        ↓
Resolve NR-07 Contextual Navigation
        ↓
Resolve NR-08 History Inspection when adopted
        ↓
Bind M6 Representation Contracts
        ↓
Validate Exposure, Continuity, and Degradation
        ↓
Publish Complete Representation Set
```

Equivalent exact inputs produce equivalent categories, identities, destination
eligibility, continuity, order, exposure obligations, degradation, and recovery.

## 7.3 Destination projection

A destination may be represented as available only when:

1. an NT contract connects the current context to it;
2. its entry conditions are currently satisfied or explicitly qualified;
3. actor access and applicable authority are known;
4. a valid Context Envelope can be restored or constructed by the owning
   navigation contract;
5. origin and return obligations are representable;
6. adoption requires explicit OI-51 or other owning OI interaction.

No heuristic, frequency, platform position, or historical visit creates
destination eligibility.

# 8. Representation Exposure Rules

Exposure rules define required professional visibility obligations, not visual
placement:

| Category | Exposure obligation |
|---|---|
| **NR-01** | Always required for an active professional context. |
| **NR-02** | Required for valid destinations relevant to current intent, reliable return, recovery, or globally guaranteed access; other destinations are conditionally retrievable. |
| **NR-03** | Required when an attributable origin is necessary for orientation, interruption, or return. |
| **NR-04** | Required whenever a valid or qualified return target exists; invalidity and fallback remain explicit. |
| **NR-05** | Required while an interruption is proposed, active, awaiting disposition, or materially changed. |
| **NR-06** | Required when suspended intent exists; may be summarized but not hidden from reliable retrieval and recovery. |
| **NR-07** | Conditional on active context and professional relevance. |
| **NR-08** | Exposed only through deliberate authorized history inspection or required recovery explanation. |

Representation may be withheld only when the category is inapplicable or an
approved equivalent retrieval/fallback preserves its obligation. Withholding
cannot hide interruption, invalid return, missing authority, stale context, or
material degradation.

# 9. Continuity Rules

1. Current context references one valid Context Envelope.
2. Origin and return identities remain separate from current context.
3. Navigation representation replacement preserves context and transition
   references rather than platform position.
4. Suspended contexts retain separate envelopes and cannot merge.
5. Cross-Matter contexts never blend Focus, Working Set, authority, or history.
6. Memory Inspection preserves the current context as return target.
7. Practice & Learning preserves production/non-production separation.
8. Interruption preserves displaced Focus, unfinished intent, class, basis,
   disposition, and return.
9. Return revalidates freshness, authority, and change-since-departure.
10. Invalid original return produces a qualified alternative, not silent Global
    substitution.
11. Representation disappearance cannot abandon professional intent.
12. Context abandonment requires OI-56 and cannot be inferred from framework
    mechanics.

# 10. Replacement and Degradation

## 10.1 Atomic replacement

```text
Current valid Representation Set
        ↓
Derive against new canonical navigation revision
        ↓
Validate categories, continuity, and M6 bindings
        ↓
Atomic representation-set replacement
        ↓
Prior set becomes obsolete
```

Replacement creates no navigation transition and changes no Navigation State,
Context Envelope, Focus, interruption, or history.

## 10.2 Degradation classes

| Degradation | Required representation |
|---|---|
| **Stale context** | Affected fields, source revision, age/condition, blocked consequences, and refresh/recovery path. |
| **Authority indeterminate** | Unknown scope, prohibited consequential adoption, and authority-resolution path. |
| **Source unavailable** | Missing source, affected categories, truthful fallback, and non-equivalence. |
| **Return invalid** | Original target, invalidation reason, preserved intent, and qualified alternative. |
| **History unavailable** | Query scope, retention/access limit, current/history distinction, and current-context return. |
| **Framework capability insufficient** | Unexpressed obligation, alternative accessible channel, or conformance failure. |

Degradation cannot fabricate a destination, infer an interruption class, restore
stale context as current, or report history as complete.

# 11. Recovery

Representation recovery:

1. validates actor identity and current authority;
2. obtains the latest canonical Navigation State revision;
3. reconstructs active, origin, return, suspended, and interrupted contexts from
   the single Context Envelope contract and source history;
4. reconciles change since the prior representation;
5. re-evaluates NT eligibility and NAV governance;
6. rebuilds the full representation set deterministically;
7. exposes missing, stale, inaccessible, or indeterminate meaning;
8. offers recovery through CIP-11/OI-55 without adopting a target automatically;
9. replaces the obsolete set only after complete validation.

Recovery creates no new Context Envelope and no Memory Event merely for
reconstruction.

# 12. Platform Navigation Framework Boundary

## 12.1 Boundary contract

```text
Navigation Representation Model
  owns M6 projection categories and preservation obligations
        ↓
Validated Navigation Representation Set
        ↓
Platform Navigation Framework
  owns platform-specific navigation mechanics
```

The validated representation set is the only handoff. The framework cannot
reinterpret navigation sources or decide professional context adoption.

## 12.2 Canonical side responsibilities

Navigation Representation Model must:

- provide exact category, context, NT, NAV, authority, origin, return,
  interruption, suspension, history, and recovery references;
- bind representations to current M6 contracts;
- state exposure, continuity, degradation, and fallback obligations;
- distinguish available, active, origin, return, suspended, interrupted, and
  historical contexts;
- reject incomplete, ambiguous, stale-as-current, or governance-invalid sets;
- remain neutral to platform navigation mechanics.

It must not:

- prescribe platform navigation primitives;
- infer navigation adoption from framework state;
- create destinations or navigation transitions;
- use framework capability to weaken governance;
- inspect framework internals as professional truth.

## 12.3 Platform framework responsibilities

A Platform Navigation Framework may implement mechanics for a valid set. It
must:

- consume the exact current representation revision;
- preserve current context, destination eligibility, origin, return,
  interruption, suspension, contextual navigation, and history distinctions;
- invoke adoption, return, interruption, or recovery only through valid CIP/OI
  contracts;
- preserve semantic order, continuity, degradation, and accessible equivalence;
- report unsupported obligations and reject stale contracts;
- avoid duplicate or fabricated professional history.

It must not:

- make platform location equal professional context;
- make framework back behavior equal canonical Return;
- infer Focus, authority, priority, lifecycle, or interruption class;
- merge suspended contexts;
- turn platform navigation records into Operational Memory;
- define a competing Navigation Representation taxonomy.

## 12.4 Framework independence

Materially different framework mechanics conform when they preserve equivalent
current context, valid destinations, origin, return, interruption, suspension,
contextual choices, history distinction, continuity, and recovery.

This document defines no Platform Navigation Framework implementation.

# 14. Conformance Criteria

A Navigation Representation realization conforms only when:

1. every set and occurrence satisfies its descriptor;
2. NR-01–NR-08 are complete and mutually bounded;
3. all sources resolve to exact Operational Navigation and Governance revisions;
4. current, destination, origin, return, interruption, suspended, contextual,
   and historical meaning remain distinct;
5. destination and return projection are deterministic and authority-safe;
6. M6 bindings preserve RN, DSR, STC, PSD, CCT, SR, and CIP ownership;
7. exposure rules preserve required meaning;
8. continuity preserves Context Envelope, Focus, origin, return, and
   cross-context separation;
9. replacement, degradation, and recovery fail safely;
10. platform framework responsibilities do not overlap navigation ownership;
11. materially different mechanics preserve equivalent navigation
    representation;
12. accessibility equivalence is demonstrable;
13. invalid and stale-as-current sets are rejected;
14. no implementation vocabulary enters the canonical representation contract;
15. all 45 invariants pass.

Pass
