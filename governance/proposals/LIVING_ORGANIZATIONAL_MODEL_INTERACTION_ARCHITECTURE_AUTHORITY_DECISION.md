- Person Workbench;

The adopted Interaction Architecture preserves the existing Product and canonical semantics.

## Adopted interaction principles

- first use begins from the organization rather than Investigation;
- useful incomplete organizational states are allowed immediately;
- no mandatory setup wizard or completeness gate;
- Organization Constructor uses progressive in-context construction;
- Organization Map preserves a stable structural base and bounded relationship lenses;
- Department Workbench prioritizes current operational understanding;
- Role and Person Workbenches remain distinct;
- Person surfaces remain purpose-filtered and privacy-constrained;
- process understanding begins from `Input → Process → Output → Result`;
- systems, SOPs, and KPIs retain distinct meaning;
- interdepartmental interactions use consistent relationship projections;
- Person-as-Source uses human-readable source selection;
- historical role and department context must be preserved;
- inherited organizational context does not automatically become Evidence, Working Set content, Hypothesis, fact, failure, benefit, or Decision;
- Investigation and Improvement remain distinct contextual work modes;
- current organizational state remains primary while history is progressively inspectable;
- Watson remains quiet, contextual, source-linked, and non-authoritative;
- incomplete, disputed, stale, unknown, and restricted states remain explicit and honest within the adopted privacy boundary.

## Responsive obligations

The responsive obligations are adopted as reviewed:

- desktop preserves the primary workspace plus focused Inspector;
- laptop preserves primary work and collapses secondary regions first;
- tablet uses a single focused context with bounded drawers or sheets;
- narrow mobile preserves orientation, inspection, history, safe correction/dispute initiation, and contextual entry while honestly degrading complex arrangement work.

Responsive adaptation does not change meaning, authority, privacy, correction rights, or historical integrity.

## Mandatory human-experience principles

- maximize useful viewport usage;
- use human-first language;
- establish comprehension before verification;
- use progressive disclosure;
- hide technical metadata by default while keeping it inspectable;
- minimize explanatory text;
- make interaction self-explanatory;
- provide clear hover, focus, and active feedback;
- use efficient information density without visual noise;
- do not give primary and secondary actions equal visual weight.

## Adopted correction effect

The controlling correction supplement is part of this adoption. Accordingly:

- a primary Map lens preserves bounded material cross-lens dependencies without becoming a universal graph;
- contextual Investigation and Improvement entry cannot reveal unauthorized person, source, subject, participation, or work-context existence;
- contribution-time role and department default only from one unambiguous authoritative effective interval, never silently from current capacity;
- narrow screens retain safe inspection and initiation of correction, dispute, response, withdrawal, and protected review;
- authorized restricted-state disclosure remains distinct from non-revealing absence for unauthorized viewers;
- authority-bearing hierarchy changes require semantic preview, while presentational arrangement remains non-authoritative.

## Human rationale

The reviewed Interaction Architecture provides a coherent and sufficiently bounded human interaction model for the adopted Living Organizational Model composition.

It allows the organizational model to become a real working environment without turning it into a setup wizard, generic database, HR dossier, decorative org chart, universal graph, or Investigation-first shell.

The corrected package also resolves the identified interaction risks concerning cross-layer dependencies, restricted existence, historical contribution-time role integrity, mobile correction/dispute rights, and non-revealing restricted states.
