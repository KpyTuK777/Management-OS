## Reconciliation disposition

### Preserve

- Investigation identity and epistemic boundaries;
- Current Situation revision history, materials, Evidence, Hypotheses, Working Set, timeline, Inspector interaction, and valid saved user data;
- shared modal foundation, focus restoration, keyboard behavior, semantic feedback, responsive patterns, and visual tokens where compatible;
- Historical Walkthrough Reader as supporting functionality;
- tested Artifact/Relationship/Memory concepts where their ownership remains valid.

### Reuse and refactor behind adopted boundaries

- reuse the existing Investigation workbench as a work mode reached from the larger shell;
- adapt Investigation persistence through a compatibility/migration adapter rather than direct deletion or semantic rewrite;
- refactor navigation and shell composition so organization is primary and Investigation remains accessible;
- generalize Inspector and modal primitives without transferring Investigation meaning into organization surfaces;
- reuse safe storage utilities and migration patterns behind the adopted versioned persistence adapter;
- reconcile Artifact/Relationship models only for their existing scopes; do not treat Matter-scoped relationships as organizational authority.

### Integrate

- contextual Investigation creation through an Organizational Context Envelope containing references only;
- a bounded Improvement entry surface with current/proposed separation;
- Operational Memory references and Historical Walkthrough navigation under current authorization;
- search-to-focus, selected organizational element, shared Inspector, and responsive navigation across the new shell.

### Supersede

- the Investigation-first landing hierarchy;
- demonstration Investigation content as the default user state;
- direct Product-domain coupling to raw `localStorage`;
- technical or Watson-first Inspector framing on organization surfaces;
- the older improvement-proposal meaning wherever it conflicts with the adopted Improvement mode.

### Retire only after verified replacement

- obsolete navigation routes and duplicate shell code;
- unreachable legacy UI paths;
- incompatible demo initialization paths.

Retirement must not remove the Historical Walkthrough Reader, saved Investigation data, or separately governed capability data. Any destructive cleanup requires explicit evidence that migration and recovery succeed.

## First-use and experience target

With no stored organization, the application shows no fabricated organization, Investigation, person, or operational content. The primary action is to create an organization through one focused input. The resulting one-organization/no-department state is immediately usable. Departments, roles, processes, systems, SOPs, measures, reports, meetings, relationships, and unknowns are added progressively from context without a wizard or completeness gate.

The application hierarchy becomes:

`Management OS → Organization → Living Organizational Model → Investigation or Improvement when chosen`

Investigation remains first-class, but no longer defines the conceptual root of the Product.
