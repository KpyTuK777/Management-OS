## 1. User and Job

**Primary user:** accountable owner or manager reviewing one completed
source-bound historical case.

**Primary job:** orient to the case, progressively inspect the fixed walkthrough,
understand Evidence, claim, source, uncertainty, hindsight, and authority
boundaries, maintain an inspectable Working Set, and provide attributable
reflection.

The first direct user is Serhii Horbachenko. This fixes the pilot participant, not
a permanent persona or market segment.

## 2. Entry and Exit Contract

Entry requires the fixed completed Knight Capital historical branch and its phase,
claim, source, uncertainty, Evidence-gap, and boundary identities. Entry must
state that reconstruction is bounded, later findings retain hindsight status,
Replay is unavailable, and H3 is unvalidated.

Exit occurs only when the user either submits attributable reflection or records
explicit deferral. Exit must preserve the Working Set and response provenance and
must not imply Replay, validation, Root Cause, causal proof, or historical completeness.

## 3. Semantic Interaction Sequence

```text
Case orientation
→ progressive phase navigation
→ Current Situation orientation
→ Evidence and claim inspection
→ source traceability
→ uncertainty and hindsight-boundary inspection
→ Working Set formation and maintenance
→ human judgment/reflection boundary
→ attributable response or explicit deferral
→ bounded exit
```

The sequence fixes semantic progression, not screen order or topology. The user
may revisit earlier material without changing historical state or claim status.

## 4. Product Interaction Contracts

### Case orientation

Must identify the case, Shape B, fixed historical scope, source limitations,
completed phases, and unavailable Replay. It must distinguish repository
completion from human participation.

### Current Situation

Must provide a readable bounded orientation to the selected phase and relevant
historical context. It is a projection of governed material, never a second source
of truth or an analyst narrative presented as fact.

### Progressive phase navigation

Must expose the phase sequence and current location while revealing detail
progressively. Phase boundaries and original claim identities remain inspectable;
navigation cannot manufacture chronology or causality.

### Evidence and claim inspection

Must let the user distinguish claim text, claim class, supporting source,
attribution, publication time, historical-knowledge status, hindsight status,
confidence boundary, contradictions, and Evidence-gap references. Claim presence
does not imply acceptance or completeness.

### Source traceability

Every substantive claim must resolve to its fixed source identity and locator.
Source access must preserve quotation/paraphrase boundaries and later-source status.

### Uncertainty visibility

Missing Evidence, contradictory support, unknown actor knowledge, missing
rationale, containment uncertainty, and differently scoped Outcomes must remain
visible at the point where they constrain understanding.

### Working Set

The user may deliberately collect, remove, order, and revisit relevant governed
material. Membership is attributable user attention, not Evidence promotion,
claim acceptance, causal proof, or canonical change. The Working Set must remain
inspectable and distinct from sources and accepted Evidence.

### Reflection boundary

Reflection begins only after direct user traversal. Prompts, responses, deferral,
respondent identity, participation basis, and time must remain attributable.
Unanswered prompts remain unanswered. Reflection does not itself validate H3.

## 5. Progressive Disclosure Rules

The interaction must:

1. begin with identity, scope, current position, and critical boundaries;
2. reveal claim detail and source metadata on deliberate inspection;
3. keep uncertainty adjacent to the constrained claim or phase;
4. allow source-level depth without requiring repository or Git knowledge;
5. preserve a return path to Current Situation and the Working Set;
6. avoid hiding provenance, hindsight, or Missing Evidence for visual simplicity; and
7. never convert summary language into stronger historical certainty.

## 6. Product States

The product meaning requires these bounded states without prescribing their
technical representation:

- oriented / not yet oriented;
- phase selected;
- claim or Evidence under inspection;
- source traceability available / source limitation visible;
- Working Set empty / populated / revised;
- reflection not reached / available / answered / explicitly deferred;
- bounded exit available; and
- degraded source access with preserved identity and limitation.

No state authorizes Replay, AI-made human judgment, or automatic validation.

## 7. Human and AI Responsibilities

The human owns attention, Working Set choices, judgment, response, deferral, and
attestation. AI may orient, summarize within fixed claims, expose traceability,
surface uncertainty, and help navigate. AI must not invent facts, infer human
answers, collapse conflicting sources, claim causality, make the human Decision,
or turn interaction completion into H3 validation.

## 8. Degraded and Boundary Behavior

- If a source cannot be opened, retain its fixed identity and disclose the access limitation.
- If support is ambiguous, stop at the stated confidence boundary.
- If claim/source linkage fails, the affected claim cannot be presented as supported.
- If attributable identity is unavailable, reflection submission must stop or remain draft.
- If the user requests Replay or counterfactual Outcome, identify the authorization boundary and do not proceed.
- If repository artifacts disagree, preserve the conflict and suspend affected synthesis.
