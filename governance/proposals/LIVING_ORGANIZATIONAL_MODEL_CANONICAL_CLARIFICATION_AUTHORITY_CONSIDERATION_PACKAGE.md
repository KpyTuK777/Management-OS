## Decision object

The accountable human is deciding whether to adopt this bounded clarification:

> The Operational Operating Model remains the sole governed organizational representational authority and owns the minimum organization-relative Element References and typed temporal Relationship Assertions required to project one non-duplicated organizational model. InformationContribution is one specialized Relationship Assertion, while all native source, Evidence, work, Decision, Outcome, identity, and Memory authorities remain separate.

## Resolution method under Option A

- **A — existing ownership clarification:** Element identity/reference, temporal/current-state, correction, and projection boundaries are made explicit under existing Operating Model authority.
- **B — bounded relationship extension:** organization-wide relationship families and InformationContribution are allocated under existing Operating Model relationship authority.
- **C — no new top-level capability:** no new aggregate, enterprise graph, Product module, database authority, or P1–P6 responsibility is introduced.

## Element identity and ownership under Option A

An **Operating Model Element Reference** would be adopted as the stable Workspace-bounded identity/reference through which the Operating Model represents an eligible organizational element.

Every reference has one explicit mode:

- source-backed reference to an authoritative native record; or
- bounded Operating-Model-owned element when no higher source owns the organization-relative identity.

Operating-Model-owned content is strictly limited to identity, kind, label, minimum topology purpose/scope, temporal status, provenance, access/sensitivity, freshness/correction metadata, and source references. Missing integration never transfers HR, SOP, system, report, meeting, KPI, execution, Evidence, work, or Memory authority.

| Element | Adopted owner/allocation |
| --- | --- |
| Organization | Operating-Model-owned root reference within one Workspace |
| Department/unit | Operating Model unless an authoritative organization source owns it |
| Role | Operating Model unless an authoritative role source exists |
| Named participant | Minimal organizational participant reference; distinct from Account/Membership and HR identity |
| Process/step | First-class referenceable operating element under existing Operational System/Operating Model authority |
| System/tool | Source-backed or minimum operational reference; no configuration authority |
| SOP | Source-backed SOP reference |
| KPI/measure | Source-backed where possible; otherwise minimum identity/definition reference, not observations or conclusions |
| Report/meeting/artifact | Source-backed where available; otherwise minimum bounded element without content/attendance authority |
| Investigation/Improvement/Decision/Outcome/Memory | External typed reference to its existing owner, never a copied Operating Model record |

Known, unknown, disputed, stale, and incomplete remain state dimensions, not entities or scores. Restricted is an access result whose existence may remain non-revealing.

## Relationship authority under Option A

An **Operating Model Relationship Assertion** would be adopted as the sole organization-relative typed, temporal relationship record.

The bounded families are:

- structural containment;
- reporting;
- role occupancy;
- department membership;
- responsibility and decision authority;
- operational participation;
- operational dependency;
- information/material flow;
- process/system/SOP/measure association;
- interdepartmental interaction;
- historical/work linkage;
- InformationContribution.

Each assertion requires stable identity, typed endpoints/roles, scope, source/authority, effective interval, recording time, provenance, state/limitations, purpose/access, and correction/supersession/dispute/redaction/deletion lineage.

It is not a generic technical graph edge. Relationship-family semantics and endpoint constraints remain mandatory. Map coordinates, layout, search, indexes, caches, and client state are never organizational truth.

## InformationContribution under Option A

InformationContribution would be adopted canonically as a specialized Operating Model Relationship Assertion—not a separate aggregate, Person history owner, or Evidence record.

It connects an exact source person, source material reference, supported context reference, contribution-time role/department, zero or more explicit subjects, and recorder where applicable. It preserves communication/recording time, knowledge basis, uncertainty, purpose/access, and correction/dispute/support/contradiction/supersession/withdrawal/redaction/deletion state.

Material content, work-context state, and Evidence status remain externally owned. Only a minimum faithful, classified excerpt may support attributable display. Source, subject, recorder, author, owner, approver, responsibility, Decision maker, Evidence, credibility, and trust remain distinct.

## Temporal and correction authority under Option A

Effective time, recording time, observation/provision time, source version/retrieval time, decision-time snapshot, and correction/dispute/supersession/redaction/deletion time remain separate.

Current state follows authority before time:

1. authorized authoritative source within scope;
2. accountable-human-approved Operating-Model-owned assertion where no higher source owns the meaning;
3. qualified attributable declarations/observations;
4. explicit derived/inferred projections.

Recency, repetition, system origin, contributor seniority, screen display, or Watson output cannot change authority. Equal-authority conflict remains disputed.

Correction, supersession, dispute, withdrawal, redaction, deletion, retirement, merge, and split have distinct semantics. Deleted IDs are never reused; tombstones are authorization-bound non-reconstructive integrity markers absent from ordinary projections.

## Reviewed update authority under Option A

- Source-backed change: native source owner approves/performs; Operating Model reconciles after validation.
- Operating-Model-owned change: identifiable human with delegated Operating Model semantic/update authority approves.
- Record custody/synchronization applies only an already authorized result.
- Investigation, Improvement, Impact Review, Monitoring, Stabilization, Memory, Watson, integrations, and projections may propose or reference; they cannot approve or apply updates.

An operational Decision does not automatically mutate the Operating Model.

## Projection invariants under Option A

Across Map, Department/Role/Person Workbenches, Process/System/SOP detail, Investigation, Improvement, and Operational Memory:

1. the same Element/Relationship identity is retained;
2. one source owner controls mutation;
3. privacy/purpose filtering occurs before projection;
4. current, historical, stale, disputed, unknown, incomplete, and restricted behavior stays qualified;
5. context does not become Evidence, Working Set, Hypothesis, fact, failure, benefit, Decision, Cause, or authority;
6. source content is referenced, not duplicated;
7. corrections/redaction/deletion propagate to projections while justified snapshots remain historical;
8. layout/client/search/index state is non-authoritative;
9. Investigation, Improvement, Decision, Outcome, Monitoring, Stabilization, and Memory retain their owners;
10. future AI is a filtered consumer with no mutation/scoring authority.
