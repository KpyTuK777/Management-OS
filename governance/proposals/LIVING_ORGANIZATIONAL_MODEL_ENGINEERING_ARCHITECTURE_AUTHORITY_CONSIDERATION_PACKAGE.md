## Architecture presented for consideration

The proposal defines one logical implementation boundary for the sole Operational Operating Model, with:

- stable Workspace-bounded Element References and typed temporal Relationship Assertions;
- source-backed authority and a minimal Operating-Model-owned fallback;
- command, query, source-resolution, temporal-resolution, privacy-policy, projection and persistence contracts;
- current records with immutable revisions and explicit correction/supersession/dispute/redaction/deletion lineage rather than full event sourcing;
- consistent privacy-filtered projections for Constructor, Map, Department/Role/Person Workbenches, process/system/SOP/KPI detail, Investigation, Improvement and Operational Memory;
- one InformationContribution assertion referenced across surfaces without copying content or Evidence status;
- explicit separation of governed, Product/workspace and ephemeral state;
- versioned crash-recoverable browser persistence behind an adapter and a future backend seam;
- rebuildable authorized search/adjacency indexes, bounded traversal and explicit incomplete results;
- honest degraded states and a filtered, source-linked, non-authoritative future Watson context boundary.

## Runtime and implementation boundary

The existing HTML/CSS/JavaScript static stack is assessed as sufficient for a broad bounded local materialization. No framework, dependency, backend or database is technically required now.

After separate adoption and implementation authorization, people-free organization construction, Map, Department/Role and operational-detail projections, interdepartmental relationships, shared navigation/Inspector, contextual Investigation/Improvement entry, Memory references, persistence, search and verification are ready to implement as one coherent product boundary.

Named-person functions, Person Workbench/search, InformationContribution activation, people-data export and certain Memory/Improvement details remain partial and policy-gated. Multi-user/server enforcement, integrations, sensitive workflows, advanced scale and Watson execution remain deferred. All implementation is currently unauthorized.

## Review record

The critical review found six bounded issues: local atomicity, saved-reference leakage, snapshot ambiguity, equal-authority conflicts, import/export trust and measurable browser-scale behavior. The correction supplement closes all six with deterministic contracts. Repeat review found no open blocker or new canonical/Product gap and classified the corrected proposal ready for neutral human consideration.

Residual risks remain browser capacity, exact people-policy parameters, absence of multi-user security in local storage, the need for empirical accessibility/privacy/performance verification, and separately authorized source integration.
