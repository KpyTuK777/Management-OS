# M8.1 — Architectural Identity and Baseline Mapping Order

## Status

```text
Completed / Scope fulfilled
```

## Direction Authority

```text
Architect Council
```

## Authority

This repository-native order refines the title and definition scope of the
already active M8.1 stage from its opening working title, `Baseline and Corpus
Mapping`, to `Architectural Identity and Baseline Mapping`.

The stage identity `M8.1`, milestone position, and single-active-stage condition
are unchanged. The earlier
[M8 Milestone Opening Order](M8%20-%20Milestone%20Opening%20Order.md) remains the
opening authority; this order supersedes only its working title and definition
task scope where they differ.

## Ordered Work

Define one implementation-independent M8.1 architectural baseline that:

- identifies Management OS as the architectural object described by later work;
- defines the system boundary and enduring architectural layers;
- assigns primary architectural responsibilities without creating governance or
  implementation authority;
- maps existing authoritative sources to those responsibilities;
- records gaps, overlaps, unknowns, assumptions, invariants, scope, and
  exclusions.

Architecture must be mapped to the system. The deliverable must not reduce the
system to a catalog or organize the system around document locations.

## Dependencies

- Canonical M7 Governance Architecture.
- Completed and canonical Milestone M7 repository baseline.
- Independently Architecture Approved M8 Architecture Vision.
- M8 Milestone Opening Order.
- Existing canonical and approved Management OS product and architecture
  sources within their recorded scopes.

## Exclusions

This order does not authorize:

- implementation, repository mechanics, runtime architecture, data models,
  APIs, components, services, infrastructure, or deployment;
- governance amendment, lifecycle change, protocol change, or new authority;
- product interaction design or interface specification;
- modification of an existing source or its authority condition;
- substantive M8.2 or later-stage architecture;
- approval, canonicalization, stage closure, or transition.

## Completion Boundary

M8.1 completed Architecture Definition, independent Architecture Review,
correction, repeat Architecture Review, Architecture Approval, Canonical Review,
and a separate canonicalization and closure transition. This order's bounded
scope is fulfilled and grants no continuing M8.1 or M8.2 authority.
