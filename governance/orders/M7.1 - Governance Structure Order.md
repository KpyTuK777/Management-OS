# M7.1 — Governance Structure Order

## Status

```text
Effective / Scope bounded
```

## Ordering Authority

```text
Product Owner
```

## Authority

This repository-native order records the Product Owner direction that opened
M7 — Governance Layer after M6 closure and authorized M7.1 — Governance
Structure as the single active architectural stage.

This order is the authoritative source for that bounded direction. The
Architecture Roadmap owns stage sequence and status, the Architecture Backlog
owns the single active task and Definition of Done, and the Chief Architect
Operating Model owns review and transition authority.

## Ordered Work

Prepare one implementation-independent Governance Layer structure defining:

- artifact-class directory boundaries;
- semantic ownership and current-model accountability boundaries;
- naming, status, and indexing rules;
- dependency direction;
- repository-truth authority;
- reserved locations for the planned M7.2–M7.7 stages without defining their
  substance.

## Dependencies

- M6 — Canonical Operational Design System — Closed.
- Existing `architecture/` control plane and repository history.

## Exclusions

This order does not:

- approve the M7.1 candidate or its dependencies;
- authorize M7.2 Constitution work;
- authorize M7.3 Organizational Model work;
- define a Development Lifecycle or Autonomous Development Protocol;
- create future roles or transfer existing authority;
- authorize implementation code or platform decisions;
- replace Architecture Review, Canonical Review, or canonicalization.

## Completion Boundary

M7.1 completes only after the candidate satisfies its Definition of Done,
receives positive independent Architecture Review, receives required positive
Canonical Review, is canonicalized through a separate repository transition,
and the roadmap, backlog, journal, indexes, and statuses agree.

Completion of this order does not itself approve or canonicalize its output.
